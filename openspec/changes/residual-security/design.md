# Design: residual-security

## Technical Approach

Three behavior-preserving/hardening workstreams, each independently verifiable:

- **WS-A (deps):** Force `glob@>=11.1.0` and `uuid@>=11.1.1` via root `pnpm.overrides`; resolve through `pnpm install`.
- **WS-B (rate-limit):** Defense-in-depth — global IP `rate_limit` at the Caddy edge + a per-user Express middleware (`rate-limiter-flexible`) on the 6 critical mutating endpoints. Built by **composition** (factory returning `RequestHandler`), mirroring the existing `createAuthenticate`/`createAuthorize` pattern.
- **WS-C (ReDoS):** Replace backtracking `PHONE_RE`/`EMAIL_RE` in `redactor.ts` with O(n) manual phone scanning + a non-overlapping linear email regex. PII redaction parity preserved.

## Architecture Decisions

| # | Decision | Option | Tradeoff | Chosen |
|---|----------|--------|----------|--------|
| A1 | Dep fix scope | Override only vs bump direct deps | Override is global, zero-code change | `pnpm.overrides` glob/uuid (transitive only; no app import found) |
| A2 | uuid module format | ESM-only assumed (proposal) vs dual ESM/CJS | Lockfile deprecation note: *"For CommonJS codebases, use uuid@11"* → CJS break risk is **low**, not Med | Treat as API-bounds risk only; audit v3/v5/v6 callers |
| B1 | Caddy limiter | `caddy-ratelimit` plugin vs Node middleware | Plugin needs custom Caddy image | Use `rate_limit` directive; **flag image build as prerequisite** |
| B2 | Health/read exemption | Matcher skip vs handle ordering | Ordering is config-only, no code | Place `/healthz` `/readyz` handles **before** `rate_limit` |
| B3 | Per-user key for `/auth/login` | JWT `sub` (spec) vs login identifier | Login has no token → no `sub` | Key by normalized `email` (body) with IP fallback; rest use `req.principal.userId` |
| B4 | Limiter placement | App-level vs router-level | Router-level matches existing composition | `router.use([paths], authenticate, rateLimit, authorize, handler)` |
| B5 | Store | `RateLimiterMemory` vs Redis | Single instance (Caddy→one dashboard:3000) | In-memory; note multi-replica gap |
| C1 | Phone redaction | Linear regex vs manual scan | Scan gives zero backtracking + substring spans | Manual run-scan + `isPhone(digits 8–15)` |
| C2 | Email regex | Anchored `^...$` (no substring) vs `(?:[A-Za-z0-9-]+\.)+` | Label class excludes `.` → no ambiguity → linear | `/[A-Za-z0-9._%+-]+@(?:[A-Za-z0-9-]+\.)+[A-Za-z]{2,}/g` |

## Data Flow

```
Client ──► Caddy (rate_limit: 100/10s/IP, health exempt) ──► Dashboard:3000
                                                             │
   /auth/login          ──► [rateLimit(email|IP)] ──► handler
   /takeover /release   ──► [auth] ──► [rateLimit(userId)] ──► [authorize] ──► handler
   /keys/.../rotate     ──► [auth] ──► [rateLimit(userId)] ──► [authorize] ──► handler
   /vectors/.../DELETE  ──► [auth] ──► [rateLimit(userId)] ──► [authorize] ──► handler
   /legal-frameworks POST ──► [auth] ──► [rateLimit(userId)] ──► [authorize] ──► handler
   (read endpoints) ──► Caddy limit only, no Express limiter
```

  limiter: RateLimiterMemory,
  getKey: (req: Request) => string,
): RequestHandler;
// Sets X-RateLimit-Limit / Remaining / Reset; 429 + Retry-After on exceed.

// redactor.ts (WS-C)
export function isPhone(s: string): boolean {       // strip \D, count 8..15
  const d = s.replace(/\D/g, ""); return d.length >= 8 && d.length <= 15;
}
// redactPii: scan runs of [+0-9()\s.-], isPhone → [PHONE];

## Testing Strategy

| Layer | What | Approach |
|-------|------|----------|
| Unit (WS-B) | 429 after bound; per-user isolation; header presence; login keyed by email | `vitest` on `createApp` with limiter injected |
| Int (WS-B) | Caddy 429 + Retry-After; health exempt | Caddy reload + `curl` loop in docker-compose |
| Unit (WS-C) | Adversarial input completes <50ms (no backtracking); parity with `redactor.test.ts` fixtures | `vitest` timeout + curated PII/non-PII fixtures |
| Verify (WS-A) | `pnpm-limit` resolves glob≥11.1.0, uuid≥11.1.1; `pnpm -r build` + `pnpm test` green | `pnpm why uuid` + CI gate |

## Threat Matrix

Routing boundary touched (Caddyfile) but no shell/VCS/PR/executable-file boundary exists:

| Boundary | Applicability | Reason |
|----------|--------------|--------|
| Documentation-like paths | N/A | No doc/executable-file handling |
| Git repo selection | N/A | No git CLI in change |
| Commit / push state | N/A | No git automation |
| PR commands | N/A | No PR automation |

Routing adversarial cases are covered by `specs/edge-rate-limiting` (429, Retry-After, health exemption, per-user isolation) — those scenarios are the RED tests.

## Migration / Rollout

- **WS-A:** add overrides → `pnpm install` → `pnpm why uuid glob` → `pnpm -r build` + `pnpm test` + docker smoke. Rollback: revert overrides + lockfile.
- **WS-B:** Caddy image must include `caddy-ratelimit` (prereq). Start generous (100/10s/IP, 20/60s/user); watch 429 logs. Rollback: remove `rate_limit` + unmount middleware.
- **WS-C:** `git revert` redactor.ts if regression; covered by tests.
